# VR Space Explorer (Unity)

A complete, playable VR-ready space exploration experience for **Unity 6 (6000.5.4f1)**.
Fly from a central space station to eight procedurally built planets, track travel
progress on a holographic HUD, and return to the hub — with or without a VR headset.

The entire galaxy is generated by one Editor utility: no manual Inspector wiring.

---

## 1. Opening the project

1. Start **Unity Hub → Add → Add project from disk** and select this repository folder.
2. Open it with **Unity 6000.5.4f1** (any Unity 6.1+ patch will offer to upgrade).
3. Let Unity restore the packages listed in `Packages/manifest.json`:
   - Unity UI / uGUI 2.0.0 (**includes TextMeshPro** in Unity 6 — the standalone
     `com.unity.textmeshpro` package is deprecated and intentionally not referenced),
   - Input System 1.20.0, XR Plug-in Management 4.6.1, OpenXR 1.17.1,
     XR Interaction Toolkit **3.5.1** (the version released for Unity 6000.5; the
     2.x line fails to compile on 6000.5 — see section 7).
4. Active Input Handling is set to **Both** (`ProjectSettings/ProjectSettings.asset`),
   so the legacy desktop input and the new Input System used by XR coexist.
5. The project uses the **built-in render pipeline** (Standard / Sprites shaders), so
   no URP/HDRP package is required and nothing extra is downloaded.

> No paid assets are used. Everything is built from primitives, procedural meshes,
> code-created materials and particle systems.

## 2. Generating the galaxy scene

In the Unity Editor choose:

**Tools ▸ VR Space Explorer ▸ Generate Galaxy Scene**

The utility then:

- creates and saves `Assets/Scenes/GalaxyExplorer.unity`,
- builds the star field, emissive sun, 8 planets (one ringed gas giant), orbit paths,
  glowing selection markers, floating name labels and the Central Space Station,
- creates the desktop player rig, the holographic screen-space HUD and a world-space
  VR canvas,
- builds an XR Origin rig (head tracking, two ray controllers, comfort locomotion)
  when the XR packages are available — it stays dormant until a headset is active,
- attaches every script and wires every button as a persistent serialized event,
- reuses generated materials under `Assets/VRSpaceExplorer/Generated/` and can be run
  repeatedly without creating duplicates.

If TMP Essential Resources have never been imported, the generator creates a dynamic
fallback font from the built-in `LegacyRuntime.ttf` automatically. To get the default
Liberation Sans SDF font instead, run
**Window ▸ TextMeshPro ▸ Import TMP Essential Resources** once.

## 3. Playing

Open `Assets/Scenes/GalaxyExplorer.unity` and press **Play**. No headset required.

### Desktop controls

| Input | Action |
| --- | --- |
| Left mouse | Click a planet in 3D or press a HUD button |
| Hold right mouse + move | Look around |
| W / A / S / D | Thrust forward / backward / strafe |
| R / F | Thrust up / down |
| Left Shift | Boost |
| Escape | Cancel travel, or toggle the help panel when idle |

### Navigation flow

1. Select a planet from the **DESTINATIONS** list or click it directly in space.
2. Press **Begin Travel** — the rig flies along an eased parabolic arc, the progress
   bar fills, an off-screen arrow points at the target and the minimap tracks you.
3. **Cancel Travel** (or Escape) stops the ship safely at its current position.
4. **Return to Hub** flies back to the Central Space Station.
5. Arrival shows a toast notification and updates the current-location display.

Free exploration is clamped to a 270-unit navigation sphere so the player can never
drift infinitely away from the galaxy.

## 4. Enabling a VR headset (OpenXR)

The desktop scene is fully playable without these steps. To enter VR:

1. Connect the headset and install its runtime (Quest Link, SteamVR, Windows MR, etc.).
2. **Edit ▸ Project Settings ▸ XR Plug-in Management** → press **Install XR Plug-in
   Management** if prompted, then on the target tab (PC standalone) enable **OpenXR**.
3. Add your controller interaction profile under OpenXR features (e.g. Touch, Index,
   Mixed Reality).
4. Press Play with the headset connected. The `XRRigBootstrap` component detects the
   active loader, enables the XR Origin, swaps in the XR UI input module and the
   Tracked Device Graphic Raycaster, and disables the desktop rig and overlay canvas.

In VR: point either controller ray at the world-space panel and pull the trigger to
select. Left thumbstick moves, right thumbstick snap-turns. Auto-travel moves the XR
Origin rig root — the tracked headset is never moved directly.

### Why the XR code is in a separate assembly

`VRSpaceExplorer.XR.asmdef` defines `VSE_XR_AVAILABLE` only when the XR Interaction
Toolkit package is actually installed (Unity version define). If the XR packages are
removed, every XR type is compiled out and the project still builds and plays on
desktop. The Editor generator talks to this assembly purely through reflection, so it
never takes a hard dependency on XR APIs.

## 6. Testing status / honest notes

- This repository was authored without a Unity Editor in the build environment, so the
  generator could not be executed here. The C# was written against Unity 6000.5 APIs,
  the uGUI 2.0 / TextMeshPro runtime and XR Interaction Toolkit 3.5.1. Every XR API
  (namespaces, component properties, TrackedPoseDriver, XROrigin) was verified against
  the 3.5.1 package source on the official package mirror.
- After running the menu command once, open the saved scene and press Play. If the
  Console reports a package resolution error, let the Package Manager finish restoring
  packages and re-run the generator.

## 7. Why XRI 3.5.1 (and not 2.x)

XRI 2.6.5's Editor debugger uses the non-generic `TreeViewItem`, which Unity 6000.5
marks as a hard error (`CS0619`) — the package itself fails to compile. XRI 3.5.1 is
the release built for 6000.5. The XR layer was migrated accordingly:

- `XRRayInteractor` → namespace `...Toolkit.Interactors`,
  `XRInteractorLineVisual` → `...Toolkit.Interactors.Visuals`,
  `XRUIInputModule` / `TrackedDeviceGraphicRaycaster` → `...Toolkit.UI`,
  `InputActionManager` → `...Toolkit.Inputs`, `XROrigin` → `Unity.XR.CoreUtils`.
- Head tracking uses the Input System `TrackedPoseDriver`
  (`UnityEngine.InputSystem.XR`) bound to HMD center-eye actions.
- The deprecated `CharacterControllerDriver` is removed (a fixed-height
  CharacterController plus the project's own `XRComfortLocomotion` is sufficient).
- `ActionBasedController` still ships in 3.5.1 as a warning-level deprecated component;
  the factory uses it (with `#pragma warning disable CS0618`) because its action
  properties remain the most compact way to feed a ray interactor, and XRI's Automatic
  input-compatibility mode still consumes it.
- All XR code stays behind the `VSE_XR_AVAILABLE` version define (now expression
  `3.0.0`) in its own assembly, so removing the XR packages still leaves a fully
  compilable, playable desktop project.
